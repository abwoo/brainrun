## §1  headline 发现：A-set 是双稳态的，产品默认值必须偏离 A-set

### 1.1 A-set 单节点有三个不动点（独立验证，非本引擎自证）

用 scipy `fsolve`（与本引擎求解器无关）求解单节点定态方程，
并用有限差分 Jacobian 求特征值：

| 不动点 | E\* | I\* | 特征值 | 稳定性 |
|---|---|---|---|---|
| 低 | 0.0730 | 0.0314 | −0.022, −0.126 | 稳定 |
| 中 | 0.1267 | 0.0496 | +0.024, −0.139 | 不稳定（鞍点） |
| 高 | 0.4750 | 0.2562 | −0.154, −0.290 | 稳定 |

初值网格长时模拟（2000 ms）确认分 basin：E0 ≤ 0.3 且 I0 高时回低点，
其余初值去高点。**这不是实现 bug，是 A-set 参数本身的数学性质。**

### 1.2 翻转阈值极低：幅度 0.1 的脉冲就永久锁死

单节点、100 ms 脉冲（A-set，G=0）：

| 幅度 | 峰值 E | 4000–5000 ms 的 E | 结果 |
|---|---|---|---|
| 0.05 | 0.103 | 0.073 | 77 ms 后回到基线 |
| 0.10 | 0.475 | 0.475 | **永久锁在高点** |
| 0.50–2.00 | 0.48–0.50 | 0.475 | 永久锁在高点 |

即：任何幅度 ≥ ~0.1 的点击都会让被点脑区永久饱和，
网络耦合下还会级联翻转全脑（均值场耦合 G=0.25 时 40/75 个脑区响应，
事后全网均值 E=0.468，不再回来）。这与 MVP 核心循环
（点击 → 响应 → 恢复 → 再点击）直接冲突。

### 1.3 演示预设（demo preset）：只改一个参数

产品默认值 `Params.demo()` = **A-set + θ_e 0 → 1.0**，
耦合用原始权重求和（TVB 惯例，见 §2），G=0.35。
改动理由与实测效果：

| | A-set | demo 预设 |
|---|---|---|
| 不动点个数（单节点） | 2 个稳定点 | 1 个稳定点 E\*=0.011 |
| 100 ms 脉冲峰值 ΔE | 0.425 | 0.482 |
| 脉冲后恢复 | 永不 | 72 ms 内回基线 |
| 全网均值 E（4000–5000 ms） | 0.468（翻转） | 0.0149（= 基线） |
| 脉冲网络响应（>0.01 的脑区） | 40/75（级联翻转） | 8/75（瞬态） |
| 500 ms 按住 | 全网翻转 | 18/75 脑区响应，恢复 |

`Params()` 仍保留纯 A-set 作为参考配置；`theta_e` 的改动、
理由与前后数字全部记录在此，不作悄悄调参。
**该预设是产品层面的选择，需用户/父代理确认；引擎本身不依赖它。**

候选预设扫描（单参数改动，均为实测）：
- b_e 2.8→3.5：单点唯一、脉冲恢复 120 ms，但均值场耦合下传播 ≈0；
  原始权重耦合 G=0.2 时 8 个脑区响应、恢复 175 ms，G=0.25 即翻转。
- c_ee 12→10 / θ_e→2.0：单点唯一且恢复快，但网络传播 ≈0。
- 振荡预设（TVB 文档 Table 1，20 Hz）：基线 E=0.32 且有持续振荡，
  脉冲峰值仅 0.16，传播 ≈0——不符合“安静基线 + 清晰响应”的要求。
- θ_e=1.0 + 原始权重耦合 G=0.35：见上表，为最优点（§5 有 G 扫描）。

### 1.4 演示预设的默认运行（`run_default.py`，5 秒）

- 基线均值 E=0.0149，最大时间标准差 2.4e-09（安静定态）
- 刺激节点峰值 ΔE=0.4824；网络平均峰值 ΔE=0.0035，最大 0.0224
- >0.01 的脑区 8/75，>0.05 的脑区 0/75；72 ms 后回到基线
- 全网均值 E（4000–5000 ms）= 0.0149，与基线一致
- E ∈ [0, 0.494]，I ∈ [0, 0.269]，P 最大 2.0

## §2 耦合与延迟口径（已定死，见模型规范 Phase 2 附录）

- 耦合：`coupling_E_i(t) = G · Σ_j C_ij · E_j(t − d_ij)`，
  C 为原始权重（0–3），即 TVB 的线性耦合惯例。
  TVB 默认斜率 0.0042 是为静息态 fMRI 调的，在本配置下单节点
  传播不可见（实测），故演示用较大斜率 G=0.35。
- 传导速度 v = **3.0 mm/ms**：TVB 源码实测
  （`tvb-library` master `tvb/datatypes/connectivity.py` L120–126
  `speed` 默认 `numpy.array([3.0])`，L522 回退值同样为 3.0；
  `delays = tract_lengths / speed`，L529）。
- 延迟步数 `idelay = rint((length / speed) / dt)`，
  四舍五入到最近整数、.5 向偶数舍入，与 TVB `set_idelays`
  （L591–615，`numpy.rint`）完全一致；权重为 0 的边 idelay=0（不用）。
  实测：dt=1 ms 时真实边的 idelay 为 2–46 步；dt=0.5 ms 时 3–92 步；
  dt=2 ms 时 1–23 步；从不出现 0 步延迟。
- 行归一化（均值场）耦合已测试并**否决**：
  - A-set + 均值场 G=0.25：40/75 脑区响应，但级联翻转、永不恢复。
  - b_e=3.5 + 均值场 G=4.0：仅 1/75 脑区 >0.01，恢复需 491 ms；
    G=6 时不再恢复，G=8 时 10/75 脑区响应但不恢复。
  - 原因：均值场把单个脑区的信号稀释到 ~20 个输入里，
    要看到传播就得把 G 推到翻转边界；原始权重求和没有这个问题。

## §3 Python ↔ Rust 对照（容差 1e-9，实测 ≤ 3.4e-16）

`compare.py`：同参数、同事件、同初值、同 dt，逐步比较全部轨迹。

| 场景 | 步数 | max\|ΔE\| | rms ΔE | max\|ΔI\| | max\|ΔP\| |
|---|---|---|---|---|---|
| default_demo（演示预设，5000 ms） | 5000 | 3.33e-16 | 3.36e-18 | 1.94e-16 | 0 |
| a_set_g0（A-set，G=0） | 5000 | 1.11e-16 | 1.64e-17 | 5.55e-17 | 0 |
| noise_seed42（噪声 0.05，种子 42） | 2000 | 5.55e-17 | 1.85e-18 | 5.55e-17 | 0 |
| nonzero_ic（E0=0.5，I0=0.3） | 2000 | 1.11e-16 | 2.79e-18 | 1.11e-16 | 0 |
| dt05（dt=0.5 ms） | 4000 | 2.08e-17 | 1.68e-18 | 6.94e-18 | 0 |
| dt2（dt=2 ms） | 1000 | 5.55e-17 | 1.91e-18 | 5.55e-17 | 0 |

结论：**两个实现在机器精度上一致**（最大偏差 3.4e-16，
约为 f64 的 1–2 个 ulp 累积），远低于 1e-9 容差。
P 轨迹逐字相同（max\|ΔP\| = 0）。

补充：Heun（dt=1 ms）与 scipy `solve_ivp` RK45（rtol=1e-10）
单节点带脉冲对照：max\|ΔE\| = 1.34e-03，max\|ΔI\| = 8.24e-04，
与 Heun 二阶精度一致（见 §8 的 dt 敏感性）。

## §5 参数响应（均按预期方向变化；边界已标出）

### 5.1 全局耦合 G（演示预设，脉冲幅度 2.0）

| G | 基线均值 E | 刺激峰值 ΔE | 网络平均峰值 ΔE | >0.01 的脑区 | 恢复 |
|---|---|---|---|---|---|
| 0.0 | 0.0111 | 0.4826 | 0.0000 | 0/75 | 66 ms |
| 0.1 | 0.0118 | 0.4825 | 0.0003 | 0/75 | 66 ms |
| 0.2 | 0.0127 | 0.4824 | 0.0009 | 0/75 | 68 ms |
| 0.3 | 0.0140 | 0.4824 | 0.0021 | 6/75 | 70 ms |
| **0.35（默认）** | **0.0149** | **0.4824** | **0.0035** | **8/75** | **72 ms** |
| 0.4 | 0.0161 | 0.4825 | 0.0097 | 23/75 | 77 ms |
| 0.5 | 0.4286（基线已翻转） | 0.0721 | 0.0332 | 67/75 | 永不 |
| 0.6 | 0.4629（基线已饱和） | 0.0024 | 0.0000 | 0/75 | — |

结论：G 在 0–0.4 内单调增强传播；**G ≥ 0.5 时基线本身翻转到高态**，
这是耦合旋钮的稳定性边界（Phase 3 旋钮范围应以此为准，默认 0.35，
上限不建议超过 0.4）。

### 5.2 刺激幅度（演示预设，G=0.35）

| 幅度 | 刺激峰值 ΔE | 网络平均峰值 ΔE | >0.01 的脑区 | 恢复 |
|---|---|---|---|---|
| 0.5 | 0.0132 | 0.0001 | 0/75 | 4 ms |
| 1.0 | 0.0747 | 0.0003 | 0/75 | 25 ms |
| 2.0（默认） | 0.4824 | 0.0035 | 8/75 | 72 ms |
| 4.0 | 0.4877 | 0.0037 | 8/75 | 72 ms |

响应随幅度单调上升，但在 1.0–2.0 之间跳变（sigmoid 陡峭所致）；
幅度 4.0 在 G=0.35 下仍安全恢复（在 G=0.4 下幅度 4.0 会翻转全网）。
Phase 3 的刺激旋钮建议用非线性映射，否则 1.0 以下几乎看不到响应。

### 5.3 抑制强度 c_ei（演示预设，G=0.35）

| c_ei | 刺激峰值 ΔE | 网络平均峰值 ΔE | >0.01 的脑区 | 恢复 |
|---|---|---|---|---|
| 2.0 | 0.4847 | 0.4451 | 71/75 | 永不（翻转） |
| 4.0（默认） | 0.4824 | 0.0035 | 8/75 | 72 ms |
| 8.0 | 0.4655 | 0.0022 | 7/75 | 46 ms |

抑制越强，传播越弱、恢复越快，方向符合预期；
**c_ei 降到 2 时刺激会翻转全网**，这是兴奋/抑制旋钮的下限边界。

### 5.4 按住（持续输入，演示预设，G=0.35）

| 按住时长 | 按住结束时节点 40 的 E | 事后全网均值 E | 结果 |
|---|---|---|---|
| 100 ms | ~0.49 | 0.0149 | 恢复 |
| 200 ms | ~0.49 | 0.0149 | 恢复（12/75 脑区响应） |
| 500 ms | 0.494 | 0.0149 | 恢复（18/75 脑区响应） |
| 1000 ms | ~0.49 | 0.2407 | **部分翻转** |
| 2000 ms | 0.499 | 0.2407 | **部分翻转** |

结论：按住 ≤500 ms 安全；**≥1000 ms 的持续输入会把网络推到
一个中间高态（全网均值 E≈0.24），松开后不恢复**。
Phase 3 的按住交互必须面对这一边界：
要么接受“按住太久会锁住，Reset 恢复”（模型本身的行为），
要么限制按住的有效时长，二选一，不可假装不存在。
（对照：G=0.4 时按住 ≥150 ms 即全网翻转；G=0.3 时按住 500 ms 仍安全，
但脉冲传播只有 6 个脑区——G=0.35 是两者间的平衡点。）

## §6 确定性

- 同种子、同事件序列重跑：Python 与 Rust 的 E/I 轨迹逐字相同
  （`assert_array_equal`；见 `test_wilson_cowan.py`、
  `crates/brain-core` 的 `determinism_same_seed_same_trajectory`）。
- 噪声：`noise_amp=0.05`、种子 42 与种子 43 的轨迹不同，
  同种子重跑相同；Python 与 Rust 的噪声轨迹最大偏差 5.6e-17
  （`compare.py` 的 `noise_seed42` 场景）。
- 默认运行（`noise_amp=0`）不使用随机数；种子参数已保留供后续使用。

## §7 边界条件：极端参数不产生 NaN/Inf

| 条件 | 结果 | E 范围 |
|---|---|---|
| 刺激幅度 20（100 ms） | 正常结束，有限 | [0, 0.5] |
| G=20 | 正常结束，有限 | [0, 0.5] |
| G=100 | 正常结束，有限 | [0, 0.5] |
| 刺激幅度 20 + G=20 | 正常结束，有限 | [0, 0.5] |

E 的上界恰为 0.5：sigmoid 饱和时 dE/dt = (1−2E)/10，
在 E=0.5 处为零——这是方程本身的界，不是钳制。
发散检查（非有限值或 |E|,|I| > 1e6 立即报错）在 Python 与 Rust
中均已实现并通过单元测试。

## §8 dt 敏感性（Heun，二阶收敛）

演示预设、2000 ms、脉冲刺激，以 dt=0.5 ms 为参照（2 ms 公共时间网格）：

| 对照 | max\|ΔE\| | rms ΔE |
|---|---|---|
| dt=1.0 ms vs 0.5 ms | 6.25e-04 | 9.39e-06 |
| dt=2.0 ms vs 0.5 ms | 3.11e-03 | 3.08e-05 |

dt 翻倍时误差放大 ~5 倍，与 Heun 二阶精度一致（理论值 4 倍，
余量来自参照本身也有误差）。默认 dt=1 ms 的绝对误差约 6e-04，
相对响应幅度 0.48 可忽略；dt=2 ms 时误差 3.1e-03，仍可用但不推荐。

## §10 Phase 3 接入注意事项

1. **默认用 `Params.demo()`（θ_e=1.0，G=0.35，dt=1 ms，速度 3.0 mm/ms），
   不要用纯 A-set**——否则第一次点击就永久锁死被点脑区（§1）。
2. 旋钮范围（实测稳定性边界）：
   - 连接强度 G：0–0.4，默认 0.35；≥0.5 基线翻转。
   - 刺激幅度：建议映射到模型单位 0.5–2.0（1.0 以下几乎无响应，
     2.0 已接近饱和；4.0 在默认 G 下仍安全）。
   - 兴奋/抑制（c_ei）：默认 4.0；降到 2 会翻转全网。
3. **按住交互**：≤500 ms 安全；≥1000 ms 会锁住网络（§5.4）。
   要么接受并说明（Reset 恢复），要么限制按住时长——不要静默截断。
4. 快照接口：引擎每步输出全部 76 节点的 E、I；
   Phase 3 的 Worker 每 1 ms 推进、约 30–60 Hz 向界面发快照即可，
   插值只做画面平滑。
5. 性能：Python 76 节点 5000 步约 1.5–3 秒；
   Rust release 下 `brain-core-run` 全程 < 0.1 秒（含 JSON 写入），
   实时求解无压力。
6. 两个实现已逐数对齐（§3），Phase 3 优先用 Rust/WASM；
   Python 保留为对照实现，任何行为疑问以它复核。

### 11.4 修掉的一个真 bug：快点击可能丢刺激

浏览器测试第一轮出现偶发失败：点击后 E 完全没动（max E = 0.012）。
原因：软件渲染下主线程卡顿时，pointerup 的处理可能晚于 180 ms 的
按住判定定时器，一次快点击被误判成“按住”；而旧 Worker 把按住事件
攒到下一个 tick 才提交进引擎，开始与结束消息若落在同一个 tick 间隙，
事件还没进引擎就被删除，刺激静默丢失；同时 pointerup 因“已是按住”
不再补发脉冲。修复（两处）：Worker 收到按住开始/结束立即提交/删除，
不经过 tick 中转；BrainScene 按住阈值 180 → 300 ms。修复后浏览器
测试连续两遍 16/16。教训：点击/按住的判定不能只依赖墙钟定时器，
事件提交路径上不能有“攒到下个 tick 再说”的间隙。

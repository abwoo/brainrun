# BrainRun MVP 深度审查报告

审查对象：abwoo/brainrun · 2026 年 11 月 11 日

## 一、先给结论：方向正确，技术基础不错，但还没达到我认为的 CHIMERA 级 MVP

我检查了仓库的实际代码结构、Rust 神经动力学引擎、Python 对照实验、Web Worker、Three.js 渲染实现，以及 Phase 1–5 的测试与验收记录。

BrainRun 已经实现了真正的神经动力学计算与 3D 交互闭环，不是一个只有发光动画的假模拟器。这一点可以肯定。

但它目前有三个核心差距：

* 科学层面：数学实现的一致性测试做得不错，但模型与真实神经生理的对应关系、连接组来源及科学验证仍需要加强。
* 物理仿真层面：已经做到刺激和网络动力学的机制性计算，但还没有 CHIMERA 那种丰富的生物结构与物理过程之间的直接操纵关系。
* 产品体验层面：已有完整的交互骨架，但距离「打开就觉得有趣、直观、值得一直探索」还有提升空间。

初步审查判断 · 基于代码与已有测试证据

| 审查维度 | 判断 |
|---|---|
| 软件工程基础 | 较好 |
| 机制性科学建模 | 有基础 |

以上是审查维度的定性判断可视化，不是经过用户研究或正式性能基准计算出的客观评分。当前无法独立运行线上交互，因此视觉体验仍需真机验证。

## 二、最重要的科学问题：你现在用的并不是真正经过验证的人类全脑连接组

这是本次审查中我认为最应该优先纠正的问题。

BrainRun 使用：

* connectivity_76.zip
* cortex_16384.zip
* regionMapping_16k_76.txt

三者来自 The Virtual Brain 的示例数据。

我进一步核对了 TVB 官方数据说明，发现这套默认连接组是基于 CoCoMac 猕猴神经示踪数据与人类 DSI 等来源构建的混合、跨物种演示性模型，而不是由某个真人的 MRI 和扩散 MRI 测得的个体化连接网络。

更关键的是，TVB 官方明确声明：这套示例数据主要用于数值测试与理论探索，存在生物物理真实性限制，不能把它直接当作高保真生物物理现实依据。TVB 2.9-18196 documentation +1

这不意味着 BrainRun 选错了数据。作为交互原型，这套数据很合适；作为严谨的人类大脑生物物理仿真，现有描述需要收紧。

建议保留为 Demo Connectome，同时：

* 在软件的模型信息里明确标注它的跨物种和示例性质。
* 不声称模拟的是某个真实人类大脑的准确连接和响应。
* 后续增加经过验证的人类结构连接图谱作为另一种模型选择。
* 将「模型数值正确」与「模型符合真实生理数据」作为两个独立的验收指标。

这项改进的意义不是增加功能，而是避免让用户误以为所有模拟结果都代表真实人脑的客观反应。

这部分比 README 的自我介绍更重要。我核对了具体实现。

| 审查项目 | 代码证据 | 我的评价 |
|---|---|---|
| 神经动力学 | brain-core/src/lib.rs 实现 E/I 群体方程 | 真实数学计算，不是假动画 |
| 数值求解 | 固定 1 ms 步长、Heun 预测—校正积分 | 方法合理 |
| 网络连接 | 76×76 连接矩阵及传导延迟 | 已有真实网络耦合逻辑 |
| 外部刺激 | StimulusEvent 进入模型方程 | 确实存在输入—响应关系 |
| 实时执行 | Rust/WASM + Web Worker | 架构正确 |
| 3D 着色 | BrainScene.tsx 从快照 E 值计算颜色 | 数据与画面有实际关联 |
| 波形 | ActivityChart.tsx 读取 E、I 状态 | 没有假造 EEG 波形 |
| 确定性验证 | Python/Rust 六组场景数值对比 | 具有可复现基础 |

尤其值得肯定的是，它做了一个比较有说服力的因果测试。

真实因果验证：将网络耦合 G 设为 0

| 被刺激脑区 | ΔE ≈ 0.483 | 仍对外部刺激产生响应 |
|---|---|---|
| 其他 75 个脑区 | ΔE = 0 | 没有经网络耦合传播的扰动 |

来自仓库 Phase 5 测试记录，在相同基线条件下比较模型扰动。

这个实验说明模型确实让其他脑区的响应依赖连接耦合，而非点击后强制点亮周围脑区。

另外，仓库记录六组 Python/Rust 对照场景的最大数值差异约为 3.33e-16。这有力支持两个实现的一致性，不过两个程序算出相同结果，不代表它们已经和真实大脑的实验记录吻合。

## 四、与你要求的 CHIMERA 式体验相比，还差在哪里？

这是我认为本次审查的重点。

| 能力 | BrainRun 当前情况 | 距离目标 |
|---|---|---|
| 精美 3D 解剖模型 | 已实现真实皮层网格、光照、旋转 | 视觉品质需真机评估 |
| 点击刺激 | 已实现，触发真实模型输入 | 基本达到 |
| 按住持续刺激 | 已实现，但可能锁定高活动状态 | 需改善 |
| 物理参数旋钮 | 4 个旋钮真正连接模型 | 已达到基础要求 |
| 实时响应 | 3D 与波形都读取模型结果 | 有待提高可感知性 |
| 自发、持续的脑活动 | 默认模型接近静态平衡 | 明显不足 |
| 直接操纵神经连接 | CONNECT 主要用于显示连接 | 尚未实现 |
| 可观察的传播过程 | 有延迟动力学，主要通过脑区颜色表达 | 不够直观 |
| 从模型中探索不同现象 | 大多围绕单一刺激与四项参数 | 探索深度不足 |
| 虚拟 EEG | 未实现 | 属于后续扩展，不必阻塞首版 |

最核心的差别

CHIMERA 的交互是：移动舌头 → 声道几何真的改变 → 声学方程重新计算 → 声音立即变化。

BrainRun 目前主要是：点击脑区 → 添加外部输入 → 神经群体状态改变 → 对应脑区颜色与曲线改变。

两个系统在计算链条上非常相似。

但在交互层面，CHIMERA 更有「直接操作一个物理对象」的感觉。

BrainRun 目前仍然更接近给模型施加刺激并观察响应，而不是直接操纵其内部生物物理结构与关系。

这就是我建议下一阶段重点突破的地方。

## 五、我发现的六个具体问题

### 问题 1：你的大脑在默认状态下可能太「安静」

优先级 P0

这是非常重要的产品问题。

在 brain-core/src/lib.rs 中，默认配置：noise_amp: 0.0

仓库实验记录也显示，默认 G=0.35 时模型趋近一个低活动稳定点，兴奋性活动 E 约为 0.011。

也就是说，如果用户什么都不做，这个模型在稳定以后基本不会持续产生明显的神经活动变化。

屏幕上虽然有缓慢旋转的大脑，但那主要是相机动画，不是神经系统的内在活动。

而你希望用户看到的是一个动态的、有生命感的物理模拟对象。

我建议增加一个经过科学定义的自发输入机制，例如：

* 带固定随机种子的、时间相关的外部噪声驱动；
* 经过验证的神经动力学振荡预设；
* 明确区分外部驱动、网络响应与自发振荡。

可以使用 Ornstein–Uhlenbeck 过程模拟具有时间相关性的背景输入，但必须正确实现随机微分方程的数值积分，不能简单往画面中加入随机闪光。

最终让用户即使不点击，也能看到由模型生成的微弱活动；点击后，外部刺激引发的变化又能清楚地区分出来。

### 问题 2：真实传播存在，但视觉上可能几乎看不出来

优先级 P0

仓库数据显示，默认刺激对局部脑区有较强响应，但只有约 8/75 个其他脑区出现大于 0.01 的瞬态变化。

同时，BrainScene.tsx 的颜色映射使用：E_BASELINE = 0.011；E_PEAK = 0.5；再将活动量映射到由蓝灰到琥珀的色阶。

这会产生一个问题：局部脑区可以明显变亮，但远端脑区的小幅度变化在同一个绝对色阶下很难看清。

并且局部刺激响应是短暂的，用户可能还没来得及观察，颜色就恢复了。

我建议不要放大虚假的神经活动，而是增加第二种真实数据可视化方式。

建议增加两种观察方式：活动强度（Absolute Activity，按照模型的 E 值着色，适合观察绝对活动强度及不同模型状态，基于 E(t)，采用固定且明确的色标）；活动变化 ΔE 视图。还应增加一个慢动作观察模式：先缓冲真实计算出来的时间序列，再按 0.25 倍或 0.5 倍速度播放。这不会改变物理方程，只是改变用户观看数据的速度。

这项改进可以显著增强「触碰后看到传播」的体验。

### 问题 3：CONNECT 还没有达到真正的直接操纵

优先级 P0

当前 CONNECT 按钮实际上是显示或隐藏选中脑区的前五条主要连接。相关实现位于 BrainScene.tsx 的连接线渲染部分。

但用户还不能直接选中一条连接并改变其权重。

这与你对 CHIMERA 的期待存在差距。

我建议把 CONNECT 从显示功能升级为交互功能。例如：用户点击一个脑区；系统显示它的重要连接；用户选中一条连接；通过直接拖动连接上的控制点改变耦合权重；模型立即采用新的网络权重计算；用户再次刺激，观察响应是否改变。

这里必须注意：视觉上的线条拉伸只是调节连接权重的交互隐喻，不应把它解释成真实轴突物理长度被改变。

当前 Rust 引擎的网络矩阵是在初始化时传入的，因此这一功能需要新增安全的运行时单边权重修改接口，并同步更新模型与 UI，而不只是改变线条粗细。

这是我认为最值得优先实现的 CHIMERA 式交互升级。

### 问题 4：长按可能导致网络锁定，破坏连续探索

在现有默认预设下，长时间刺激可能使网络进入高活动状态，用户需要点击 RESET 才能恢复。

从非线性动力系统角度，这并不必然是程序错误。模型可能确实进入了不同的吸引子或持续高活动状态。

但对一个完全没有神经科学基础的用户而言：他只是按住了鼠标，大脑却突然一直很亮，之后不再按预期响应。这会让人怀疑软件卡住了。

建议首版增加一个默认的安全探索预设，确保普通短脉冲和常规长按能够重复体验；同时保留可以进入高活动状态的高级实验预设。

当系统真的进入持续高活动状态时，应该直观解释：「网络进入了新的稳定状态」，同时提供一键恢复或撤销最近一次实验，而不是简单提示「网络已锁定」。

不能为了交互方便而偷偷重置或伪造衰减；应采用经过验证的稳定参数区间，或者明确显示用户触发了模型状态切换。

### 问题 5：界面上的专业术语仍然偏多

你希望这个软件低门槛，但现在 UI 里仍然有：EXC / INH；c_ei = 4.0；G = 0.35；REGIONAL NEURAL ACTIVITY；lHC、lAMYG 等脑区缩写。

这些对于神经科学研究人员没有问题，但普通用户不容易理解。

我建议保留精确科学参数，同时加入直观层与专业层：默认显示「刺激有多强？」（Stimulus amplitude / P）、「大脑有多容易被抑制？」、「脑区之间有多强的影响？」（Global coupling）、「这个区域有多活跃？」（Excitatory population activity E）、「这是哪个位置？」（图谱名称、区域编号与空间坐标）。

普通用户应该首先理解操作会造成什么变化，而不是参数叫什么。

此外，当前部分字采用约 10–11 px 的大小。即使在 1920 px 桌面环境下可能还能看清，对手机、平板和高 DPI 设备的可读性也应该单独测试。

### 问题 6：还有发布与工程方面的缺口

这是另一个不能忽略的部分。

数据许可。目前仓库已提交了由 TVB 原始数据转换得到的 vertices.bin、triangles.bin、connectivity.json 等资产。README 虽然说明原始数据不进仓库，但这并不自动解决衍生数据的再分发许可问题，需要确认 TVB 数据许可。

代码许可。README 声称采用 MIT，但仓库文件清单中没有根目录 LICENSE 文件。建议在核实数据授权后，补上准确的代码许可证，并将第三方资产单独说明。

性能验证。Phase 5 的记录非常诚实：软件渲染环境下只有约 0.8–1 FPS，而真实 GPU 下的目标帧率尚未验证。这个数字不能用来认定你的项目在 Apple Silicon Mac 上也只有 1 FPS，但同样不能说它已经达到 CHIMERA 的流畅程度。

首次加载。现有代码在大脑网格加载完成后就可能允许点击，而 Worker 的 WASM 引擎可能还没有准备好。过早点击可能产生视觉确认，却没有真正执行刺激。建议在引擎就绪前禁用刺激并显示明确的就绪状态，或者缓存点击并在实际执行时给出反馈。

运行时分配。Rust step_one() 中仍有多个 Vec 分配、状态克隆和历史数组维护。76 节点规模目前可以运行，但若要进一步接近 CHIMERA 对实时性能的要求，应逐步改为可复用缓冲区和固定容量延迟环形缓冲区。

## 六、科学方法上，我还建议补三个验证层次

你目前的验证偏重于程序是否正确执行既定数学模型。

下一步应把验证明确分成三个层次。

| 验证层次 | 当前状态 | 需要增加什么 |
|---|---|---|
| 数值正确性 | 已有较完整的 Python/Rust 一致性与步长测试 | 增加与 TVB 官方运行结果的独立对照 |
| 动力学机制正确性 | 有参数扫描、平衡点及刺激对照 | 增加相图、稳定性区域、网络响应传播的定量分析 |
| 生理有效性 | 尚缺充分的经验数据验证 | 用具有明确物种和条件的真实神经活动数据约束模型行为 |

这里还有一项原则需要明确：Wilson–Cowan 本质上是神经群体平均活动的现象学模型，并不是从完整离子通道和神经组织电磁场出发的第一性原理物理求解器。它属于机制性神经动力学建模，适合你当前的 MVP，但严格的生物物理保真度低于复杂细胞电生理模型。

所以 BrainRun 与 CHIMERA 建模哲学相近，数学物理细节不在同一层次。

你不需要因此立刻改成 Hodgkin–Huxley 全脑仿真。那会大幅增加复杂度，却未必提升低门槛体验。

更合理的是先把现有模型的真实性边界讲清楚，并让每一个可交互参数都有充分的机制解释。

## 七、我建议下一轮按这个优先级修改

* PR 1 — 科学基础与发布合规：明确 TVB 76 区数据的混合跨物种来源；核实数据许可；补充代码许可证；与 TVB 官方实现进行独立数值对照；把数学一致性与生理真实性区分开。
* PR 2 — 让真实因果反馈更容易被看见：加入活动变化 ΔE 视图、可回放的刺激响应时间窗口、慢动作播放、基于真实计算的脑区响应高亮。不要引入任何独立制造的神经活动动画。
* PR 3 — 真正的直接操纵：允许选中连接并改变其权重；允许对选中脑区施加兴奋或抑制性外部输入；改进点击标记，使其出现在鼠标实际触碰的表面位置，而不是统一放在脑区中心。
* PR 4 — 真正有生命感的默认状态：为模型增加经过验证、带确定性随机种子的背景驱动或振荡预设，保留安静基线模式；调整容易锁定的长按体验，并增加可恢复的实验状态。
* PR 5 — 真机体验与低门槛验收：在 Apple Silicon Mac 上测量帧率、响应延迟和 10 分钟稳定性；修复加载期间无效点击；检查 Safari 与触摸操作；组织至少五名非神经科学背景用户完成无教程操作测试。

这一轮我反而不建议立刻增加虚拟 EEG、多尺度神经元、头骨切面或复杂模型市场。

你需要先把已经存在的核心功能真正做出吸引力。

## 八、最终应当怎样验收下一版？

我建议增加几个比现在的自动化测试更贴近产品目标的验收场景。

BrainRun 下一轮 MVP 验收清单（0/10）：

1. 第一次打开，无教程也能在 10 秒内找到并完成一次刺激
2. 默认状态下的活动来自真实模型，不依赖装饰性随机闪光
3. 点击后，能够明显区分输入标记、局部响应和网络响应
4. 能切换绝对活动与刺激响应变化视图
5. 能直接改变至少一条连接的权重，并观察由此产生的响应差异
6. 同一实验可以以慢动作回放，且结果与原始仿真一致
7. 复原相同参数和随机种子，能够重复相同实验结果
8. 长按产生持续高活动时，用户能够理解并恢复
9. Apple Silicon 真机上流畅运行，视觉交互没有明显卡顿
10. 科学模型、图谱来源、许可和性能限制均如实标注

## 九、最终判断

我认为你现在的 BrainRun 已经完成了一个具有真实机制性计算核心的技术 MVP。它有实际的神经动力学方程、网络耦合、刺激事件、WASM 执行和能够验证的输入—响应链条。

尤其是 Python/Rust 对照与因果测试，比很多只有三维演示效果的项目扎实得多。

不过，如果按照你真正追求的 CHIMERA 标准，我现在还不会将它认定为最终完成。

因为你想要的是：用户仿佛在触碰、改变和探索一个真实运行的生物物理世界，而不是对着一张大脑模型不断点击，再看几个数值改变。

要实现这个目标，我认为最重要的不是再加十个功能，而是把三个体验做透：第一，让大脑本身有来自模型的持续动态。第二，让每一次真实的因果变化都清楚可见。第三，让用户能够直接操纵神经网络的内部关系，而不仅仅是施加外部刺激。

做到这三件事，再完成科学数据来源和真实设备性能的验证，BrainRun 才会真正接近你想象中的 CHIMERA 式大脑物理模拟器。

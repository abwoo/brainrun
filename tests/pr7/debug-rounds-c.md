## Round 1 — 核心模块初版与标定（2026-11-12）

- 写 `app/src/lib/experiments.ts`（JR 六维步进器 + A/B + 时间机器 +
  PID/闭环 + 适应）与 `reference/python-model/experiments_pr7.py`（同公式）。
- Python 自检首跑即发现两个标定问题（不是代码 bug，是参数选错）：
  - 阈值 0.5 µV 高于响应峰值（Pz 峰 ≈ 0.19 µV），闭环永不触发 →
    改阈值 0.1 µV + 测量噪声 0.02 µV，首触发 1044 ms、时延 44 ms。
  - PID kp=2、ki=1 在一阶植物（τ=200 ms）上慢极点时间常数约 2.9 s，
    2 s 内稳态误差 0.12 → ki=10，安定 388 ms、超调 0%。
- 测量脚本 bug 一则（已修，不是产品问题）：oracle 对照里驱动窗口
  取了步末时刻而非步初时刻，导致 y0 差 0.0022 mV；改回步初后差 0.0。
- `TimeMachine.restore()` 缺陷（产品问题，已修）：恢复后恢复点快照
  本身不在历史里（分支点处少一个快照），现恢复时补进；TS 与 Python
  两边同修。
- 误触发率口径：全程 2.0% 来自前 252 ms 滑窗建窗期（窗未满、功率
  估计方差大）；建窗后（t ≥ 300 ms）0.34%，< 1%。测试断言建窗后值，
  全程值只作记录。

## Round 2 — 测试口径修正（2026-11-12）

- TS 测试首跑 18/20 通过，两处失败均为测试口径问题（不是产品问题）：
  - 平坦基线（p0=90 不动点）的 PSD 峰无意义：TS 124.76 Hz vs
    Python 1.22 Hz，都是数值噪声的峰。改断言为沉降段方差
    （基线 < 1e-12 mV²、极限环 1.7e-4 mV²）+ 极限环峰 10–12 Hz。
  - 分支分叉量：0.5 ms 全轨迹采样 0.07760 mV vs 10 ms 快照采样
    0.07755 mV，差约 5e-5 mV 是采样网格不同。全轨迹对照容差放
    1e-3 mV（有实测依据），快照网格对照保持 1e-9。
- 修正后 TS 21/21、Python 16/16 全绿。

## Round 3 — 拉伸项深度偏置：eLORETA 权重坍缩（2026-11-12）

- 深度加权 / dSPM 先行验证通过（numpy 原型）：深源 55.43 → 45.25 /
  dSPM 0.00 mm；浅源 dSPM 55.43 mm（变坏，如实记录）。
- eLORETA 初版 TS 与 Python 峰值不一致（TS 深源 [16,16,−16]、
  Python [48,48,48]），其余方法全部一致。诊断：标量 eLORETA
  权重迭代缺少归一化——权重方程尺度不变，不归一化时 w 沿尺度方向
  几何坍缩（每轮约 ×0.7），17 轮后触 1e-300 下限、权重全为 1e-150，
  终解沦为任意峰；TS 与 Python 在 denormal 区落在不同峰上。
- 修复：每轮把 w 按最大值归一化（两边同修）。归一化后 12 轮收敛
  （max 相对变化 0.00091 < 1e-3），深源 32.00 mm、浅源 78.38 mm，
  TS/Python 逐项一致。权重迭代与数据 V 无关（只取决于 lead field
  与 λ），是不动点性质。
- 另修 Python `depth_reference.py` 的 `_peak_and_spread`：dSPM
  传入的是 64 维每源值、不是 192 维分量，reshape 报错；加
  `already_norms` 参数。
- 修正后深度测试 TS 6/6、Python 5/5 全绿。

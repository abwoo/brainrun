## 2. 问题清单

### L-01（低）：HeadSphereLab 与 DipoleLab 控制区容器 +4px 横向溢出

- 面板：HeadSphereLab、DipoleLab；宽度：1920 与 978 均有。
- 描述：控制区外层 `div` 的 `scrollWidth − clientWidth = 4px`，
  `overflow-x: visible`。内容是“可直接操作的物理参数 / 电流源控制”
  一行，内含电极布局、源方向等下拉框与滑杆。
- 目视复核：两张 headsphere 截图里看不到任何遮挡或内容丢失，
  4px 差异不可见，疑似 flex 行 gap/内边距的取整残留。
- 截图：`tests/pr8/layout-shots/1920x1080_headsphere.png`、
  `tests/pr8/layout-shots/978x800_headsphere.png`。
- 第二阶段：顺手排查该 flex 行，确认 4px 来源并消除。

### L-02（低）：源定位 tab 的 λ² 数字输入框值显示不全

- 面板：EegAnalysisLab → 源定位 tab；宽度：1920 与 978 均有。
- 描述：λ² 输入框的值是未格式化的完整浮点数
  `0.1111111111111111`，框 `style width: 72px`、实占 64px，
  `scrollWidth 130px`（+66px），框内只能看到 `0.11111`，其余被裁。
  同 tab 其余 4 个数字输入框（真源 X/Y/Z=16、MNE 噪声 σ=1）均无溢出。
- 目视复核：978 截图里该框显示 `0.11111`；下方对照表里写的是

- 截图：`tests/pr8/layout-shots/978x800_eeglab-源定位.png`。
- 第二阶段：把该框的值格式化为 3 位小数（与表内一致），或放宽输入框。

## 4. 启发式无教程走查

方法：假装第一次打开产品的非专业用户，不看任何教程，完成四项核心操作。
脚本化走查（`audit-layout.py` 的 `walkthrough`，1920×1080，新开页面）：

| 步骤 | 结果 | 证据 |
|---|---|---|
| 1. 选脑区 | ✓ 通过 | 悬停 3D 大脑中央出现提示 `lCC — 点击刺激 · 按住持续输入`；点击选中 lCC #75，REGION / CONNECTION 面板出现选中反馈 |
| 2. 给刺激 | ✓ 通过 | 同一次点击即触发刺激；右侧响应面板出现 `基线：刺激前 t=28.16 s · lCC #75`，响应列表列出 `lCC #75 峰值 ΔE +0.482` |
| 3. 看 EEG | ✓ 通过 | 顶栏 `EEG 分析` 入口直接找到；点运行实验后波形渲染（`eeg-waveform` 可见） |
| 4. 换模式 | ✗ 不存在 | 全页按钮逐一比对：`PLAY / WAVES / EEG / EXPLORE` 均无同名独立按钮；顶栏 PLAY 的完整文本是 `PLAY — 运行中`，那是播放/暂停，不是模式切换 |

补充说明：

- 走查里记录的时间（选脑区 29.8 秒、总计 69 秒）被截图超时污染：
  三张走查截图各花了 10 秒超时等待，实际交互（悬停→点击→反馈）
  约 2–3 秒。不要把这个数字当成首次操作时间。
- 首次刺激的发现性只靠两处：一是悬停大脑才出现的浮动提示，
  二是底栏小字“点击刺激 · 按住持续输入”。不悬停、不读底栏，
  新人不知道大脑是可以点的——这是走查里最弱的一环。
- 刺激与响应的因果链要靠视线跳跃：点在 3D 舞台中央，反馈在右侧
  “刺激响应”面板。走查脚本能直接读到反馈文字，但真人需要自己
  把“刚才点那一下”和“右边多了一块基线文案”联系起来。
- 点中的是 lCC #75（PR2 已知的零连接脑区，峰值 ΔE +0.482）——
  恰好验证了点击刺激在零连接脑区上也能正常出响应。
- 第一轮走查作废：误点了 LIVE ACTIVITY 的小 canvas（页面第一块 canvas），
  不是 3D 大脑；原因是当时脑数据资产缺失、3D 舞台是报错空态。
  第二轮起改取 `section.stage canvas`，并补齐脑数据后重做，
  本节结论以第二轮（瘦身跑）为准。

### 离“80% 首次使用者无协助完成核心任务”还差什么

按 2.0 计划第十九部分 D，缺口清单（按优先级）：

1. **模式切换入口不存在（结构性缺口）**：PLAY / WAVES / EEG / EXPLORE
   四模式是 2.0 的核心导航，本基线没有。等 A 路第二阶段合入后，
   按 `docs/no-tutorial-user-test-protocol.md` 重做真人测试。
2. **首次刺激的发现性**：给 3D 舞台加一个常驻的、不用悬停就能看到的
   操作提示（例：舞台角落常驻“点击大脑给刺激”），不要只依赖悬停
   提示与底栏小字。
3. **刺激→响应的因果可视性**：点完大脑后，除了右侧面板更新，
   舞台内应有一次明确的即时反馈指向响应位置（例：被刺激脑区短暂高亮
   + 一条“去看右侧响应”的视觉引导），让新人自己建立因果。
4. **EEG 分析的空态引导**（L-05）：空记录时各 tab 给一句引导文案。
5. **LocalBEM 的空态引导**（L-06）：无模型文件时说清状态，不要只留导入框。
6. **978px 下核心参数的可达性**（L-04）：PARAMETERS 面板离舞台太远，
   考虑就近放置或锚点。
7. **顶栏窄屏拥挤**（L-03）：978 下 chip 竖排单字，收窄或换行。

## 根因（修前复测确认）

1. **CONNECTION 滚不到**：定高面板（LIVE 194 + RESPONSE 738 +
   BACKGROUND 391 + PARAMETERS 394 ≈ 1717px）塞进 980px 高的 `.main`，
   只有 `.region-panel` 能内部滚，于是它被 flex 压扁到 44px；
   `.panels` 本身 `overflow: visible`，列内容溢出 100vh 的 `.app`，
   逼出文档滚动，CONNECTION 主体既不在列内也不在文档滚动的可点位置。
   修法：`.panels` 改为滚动容器、REGION 改为普通面板随整列滚动、
   `.app` 加 `overflow:hidden`、LIVE 用 sticky 置顶。
2. **第二屏纯黑空地**：第 1 条的文档滚动所致——滚到底后左列舞台
   之下没有任何内容。文档滚动消除后，空地随之消除。
3. **手机顶栏**：无 ≤768px 断点，16 个 chip 在 390px 下折成 7 行。
   修法：新增断点，顶栏单行横向滚动。另核实：390 下舞台实测
   374px 宽（脑列可用），“只剩约 40px”是源码推断有误；主布局
   也无固定 320px 侧栏，320px 只在三处 tab 网格的 minmax 里，390 下
   内容宽 338px、单列能放下。
4. **弹窗按钮初次不可见**：模型信息弹窗整框滚动，底部按钮在
   内容最末（修前 y=1431）。修法：弹窗纵向 flex，正文为唯一滚动区，
   按钮移入固定底部；七台统一封顶 86vh。
5. **L-01**：Chromium 给 `input[type=range]` 默认 `margin: 2px`，
   `width:100%` 的滑杆右缘比容器多 2px、两侧共 +4px scrollWidth。
   不是 flex gap 取整残留。修法：`.modal input[type=range] { margin: 0; }`。
6. **L-02**：λ² 框存完整浮点数未格式化。修法：框内显示
   `toFixed(3)`（0.111），与对照表一致；状态仍存完整值，不改计算。

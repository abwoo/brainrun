# PR3 debug rounds

纪律：每轮 = `npm run build` → Phase 3（16 项）→ Phase 4（23 项）→ PR2 正式测试
（`tests/pr2/pr2-test.py`，56 项）→ PR3 正式测试（`tests/pr3/pr3-test.py`）。
任一轮失败就修，修完从第一轮重新开始计轮，不许只重跑失败的那一项。
时间均为北京时间（CST）。

前置已验证（不计轮，见对照脚本输出）：
- Rust 单元测试 `cargo test -p brain-core`：PR3 新增 4 项全过（含 3 节点链
  清零/加倍、单边+clamp、偏置正负、RESET 保留权重清偏置）；Python 镜像
  测试 `python3 -m unittest test_pr3` 4/4，旧 11 项回归全过。
- WASM↔Python 76 区逐值对照（`tests/pr3/crosscheck-*.py/mjs`）：8 个场景
  采样轨迹最大差 ≤ 9.4e-16；因果表：脉冲 73 → 峰值 ΔE[54] 基线 0.0270、
  W[54][73]=0 后 0.0013（4.8%）；脉冲 69 → 峰值 ΔE[40] 基线 0.0039、
  W[40][69] 1.0→2.0 后 0.0084（2.19×）；稳态 E[40] 无偏置 0.0118、
  +0.5 → 0.0250、−0.5 → 0.0061、清除后 0.0118；未连接节点 0 的 E 在
  三种偏置下均为 0.0135（差 < 1e-9）。
- 关键发现（扫描实测）：76 区密连接网络里多数单边对下游峰值几乎无影响
  （多跳路径主导），只有少数边占主导——73→54（W=3.0）清零后剩 4.8%，
  69→60（W=3.0）剩 12.3%，40→59（W=2.0）剩 18.5%；浏览器测试用
  73→54（清零）与 69→40（加倍，W=1.0→2.0）这两对。

- PR2 正式测试：56/56 通过（峰值 ΔE[40]=0.4799、响应 9 个、回放峰值三方
  相等 0.491691073683251、0.25× 比值 0.25、零控制台报错）。
- PR3 正式测试：**19 项通过后在 WU10 处崩溃**——W1–WU9 全过（清零后峰值 0.00128、
  基线 0.02699、比值 0.048；加倍 0.00835 vs 基线 0.00383、2.18×；
  单边、clamp、恢复、面板编辑、RESET 保留权重均通过），在 WU10 处
  `TimeoutError`：RESET 后再脉冲 73，响应列表里没有 54 号脑区。
- 根因（**测试 bug**，产品行为正确）：WU9 刚验证 RESET 保留了 W[54][73]=0.5；
  WU10 又用脉冲 73 来重选 54，但 0.5 的权重已把 54 对 73 脉冲的响应压到
  0.01 阈值以下，54 不再是响应脑区、列表里自然没有它——这本身正是
  “权重被保留且生效”的证据，不是产品故障。
- 修法（只改 `tests/pr3/pr3-test.py`，产品代码未动）：WU10 改脉冲 55
  （它到 54 的边 W=3.0 从未改过，54 仍响应），再点响应行重选 54 查徽标。
- 按纪律作废本轮，修完重新从第 1 轮开始。
